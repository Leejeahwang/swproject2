1. 프로젝트 개요
================================================================================

【프로젝트명】
물품 대여 플랫폼 (Rental Sharing Platform)

【목적】
사용자 간 물품을 안전하게 대여하고 공유할 수 있는 웹 기반 플랫폼

【주요 기능】
- 사용자 인증 (회원가입, 로그인)
- 물품 등록 및 관리
- 물품 검색 및 필터링 (카테고리, 지역, 키워드)
- 대여 신청 및 승인 프로세스
- 2단계 반납 확인 시스템
- 실시간 채팅
- 리뷰 및 평점 시스템 (대여 내역, 프로필, 제품 상세 페이지)
- 실시간 알림 기능
- 사용자 프로필 및 찜 기능

2. 프론트엔드 → 백엔드: POST /api/rentals (JWT 토큰 포함)

6. 백엔드 → 프론트엔드: 응답 (성공/실패)
7. 프론트엔드: 화면 업데이트 + 알림 표시

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▶ 회원가입 프로세스
------------------
1. 프론트엔드: 사용자가 입력한 정보 수집
   - username, email, password, phone, location

2. 백엔드 (routes/users.js):
   ```
   POST /api/users/register
   
   ① 이메일 중복 체크
   ② 비밀번호 해싱 (bcrypt.hash - 10 rounds)
   ③ UUID로 고유 ID 생성
   ④ 사용자 정보 저장 (averageRating: 0)
   ⑤ JWT 토큰 생성 (userId 포함)
   ⑥ 토큰 반환
   ```

▶ 로그인 프로세스
----------------
1. 백엔드 (routes/users.js):
   ```
   POST /api/users/login
   
   ① 이메일로 사용자 검색
   ② 비밀번호 비교 (bcrypt.compare)
   ③ 일치 시 JWT 토큰 발급
   ④ 토큰 반환
   ```

▶ JWT 토큰 구조
--------------
```
Header: { alg: "HS256", typ: "JWT" }
Payload: { id: "user-id" }
Signature: HMACSHA256(header + payload, SECRET_KEY)
```

▶ 인증 미들웨어 (middleware/auth.js)
-----------------------------------
```
모든 보호된 API 요청마다 실행:

1. Authorization 헤더에서 토큰 추출
   → "Bearer <token>" 형식

2. jwt.verify()로 토큰 검증
   - 유효기간 체크
   - 서명 검증

3. 토큰에서 userId 추출
   → req.user에 사용자 정보 저장

4. next()로 다음 미들웨어/라우터로 전달

실패 시 → 401 Unauthorized
```

▶ 프론트엔드 인증 관리 (AuthContext)
-----------------------------------
```
- Context API로 전역 상태 관리
- localStorage에 토큰 저장
- 자동 로그인 (토큰 유효성 확인)
- PrivateRoute로 페이지 접근 제어
```

【4.3 대여 프로세스 (핵심!)】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▶ 대여 상태(Status) 관리
------------------------
```
pending    → 대여 신청됨 (승인 대기)
approved   → 예약 확정 (대여 시작 가능)
ongoing    → 대여 진행 중
returning  → 반납 요청됨 (확인 대기)
completed  → 대여 완료 (리뷰 작성 가능)
cancelled  → 대여 취소됨
```

▶ 대여 프로세스 흐름도
---------------------
```
[빌리는 사람]                          [빌려주는 사람]

    대여 신청
       ↓
  (pending) ────────────────→  승인 / 취소 선택
                                      ↓
                                   승인
                                      ↓
  예약 확정 확인 ←──────────────  (approved)
  (approved)
       ↓
  사용 시작
  (ongoing)
       ↓
  반납 요청
  (returning) ──────────────→  반납 확인 대기
                                      ↓
                                 반납 확인
                                      ↓
  대여 완료 ←────────────────  (completed)
  (completed)
       ↓
  리뷰 작성
```

▶ 주요 API 엔드포인트
-------------------
```
1. POST /api/rentals
   - 대여 신청 (status: pending)
   - 알림 생성 (물품 소유자에게)

2. PUT /api/rentals/:id/approve
   - 대여 승인 (pending → approved)
   - 알림 생성 (신청자에게)

3. PUT /api/rentals/:id/cancel
   - 대여 취소
   - 빌리는 사람: pending만 취소 가능
   - 빌려주는 사람: pending, approved 취소 가능
   - ongoing은 양쪽 모두 취소 불가

4. PUT /api/rentals/:id/return
   - 반납 요청 (approved/ongoing → returning)
   - 빌리는 사람만 호출 가능
   - 알림 생성 (빌려주는 사람에게)

5. PUT /api/rentals/:id/complete
   - 반납 확인 (returning → completed)
   - 빌려주는 사람만 호출 가능
   - 알림 생성 (빌리는 사람에게)
```

▶ 날짜 중복 방지 로직
-------------------
```
대여 신청 시:
1. 해당 제품의 모든 대여 내역 조회
2. 'ongoing' 또는 'approved' 상태만 필터링
3. 신청 날짜(startDate ~ endDate)와 겹치는지 확인
4. 겹치면 → 400 에러 ("이미 예약된 날짜")
5. 안 겹치면 → 대여 생성
```

▶ 대여 가격 계산
--------------
```
일일 단위로 고정:
totalPrice = pricePerUnit × days

예시:
- 대여 가격: 10,000원/일
- 대여 기간: 3일
- 총 가격: 30,000원
```

▶ 2단계 반납 프로세스 (보안 강화)
--------------------------------
```
목적: 빌린 사람이 반납하지 않고 도망가는 것을 방지

1단계 (빌리는 사람):
  - "반납하기" 버튼 클릭
  - status: returning
  - 빌려준 사람에게 알림

2단계 (빌려주는 사람):
  - "반납 확인" 버튼 표시
  - 물품 확인 후 클릭
  - status: completed
  - 빌린 사람에게 완료 알림

→ 양쪽 동의가 있어야 완료!
```

【4.4 실시간 채팅 (Socket.io)】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▶ Socket.io 동작 원리
--------------------
```
WebSocket 프로토콜 기반:
- HTTP와 달리 지속적인 연결 유지
- 양방향 실시간 통신
- 서버 푸시 가능 (클라이언트 요청 없이)
```

▶ 채팅 구현 (server.js)
----------------------
```javascript
1. 연결 설정:
   io.on('connection', (socket) => {
     // 클라이언트 연결됨
   })

2. 채팅방 입장:
   socket.on('join_room', (roomId) => {
     socket.join(roomId); // 특정 방에 입장
   })

3. 메시지 전송:
   socket.on('send_message', (messageData) => {
     // 메시지 DB 저장
     // 해당 방의 모든 사용자에게 전송
     io.to(roomId).emit('receive_message', messageData);
     
     // 상대방에게 알림 생성
     createNotification(...);
   })
```

▶ 채팅방 ID 생성 규칙
--------------------
```
두 사용자 ID를 정렬하여 조합:
예) user1: "abc", user2: "xyz"
→ roomId: "abc-xyz"

→ 양방향 채팅 보장 (누가 먼저 시작해도 같은 방)
```

▶ 프론트엔드 채팅 (ChatRoom.js)
------------------------------
```javascript
1. Socket 연결:
   const socket = io('http://localhost:5001');

2. 방 입장:
   socket.emit('join_room', roomId);

3. 메시지 수신 대기:
   socket.on('receive_message', (message) => {
     setMessages(prev => [...prev, message]);
   });

4. 메시지 전송:
   socket.emit('send_message', {
     roomId, senderId, content, senderName
   });
```

  원본: "mypassword123"
  해시: "$2a$10$..."

【API 보안】
----------
▶ Protected Routes:

7. 실시간 통신 (채팅)
================================================================================

【Socket.io vs HTTP】
-------------------
HTTP (기존 방식):
  - 요청 → 응답 → 연결 종료
  - 실시간성 부족
  - 서버 푸시 불가

Socket.io (WebSocket):
  - 지속적인 연결 유지
  - 양방향 통신
  - 실시간 이벤트 전송

【채팅 프로토콜】
---------------
클라이언트 → 서버:
  - join_room
  - send_message

서버 → 클라이언트:
  - receive_message
  - user_joined (선택)

【채팅방 격리】
-------------
socket.join(roomId):
  - 특정 방에만 메시지 전송
  - 다른 방 사용자는 수신 못함
  - io.to(roomId).emit()

GET    /api/notifications/count    - 읽지 않은 알림 개수
PUT    /api/notifications/:id/read - 알림 읽음 처리
PUT    /api/notifications/read-all - 전체 읽음 처리

【예상 질문 대비】
---------------
Q1: "왜 Lowdb를 사용했나요?"
A: 프로토타입 개발에 적합한 경량 DB입니다. 실제 서비스에서는 
   MongoDB나 PostgreSQL로 마이그레이션할 수 있습니다.

Q2: "Socket.io가 정확히 어떻게 동작하나요?"
A: WebSocket 프로토콜을 기반으로 클라이언트와 서버 간 지속적인 
   연결을 유지하여, 양방향 실시간 통신을 가능하게 합니다.
   특정 채팅방(room)에 join하여 해당 방의 사용자들에게만 
   메시지를 broadcast합니다.

Q3: "JWT 토큰이 탈취되면 어떻게 되나요?"
A: 보안 위험이 있습니다. 개선 방안으로는:
   1) HTTPS 사용 (암호화 통신)
   2) 토큰 유효기간 짧게 설정
   3) Refresh Token 도입
   4) HttpOnly Cookie 사용

Q4: "대여 날짜 중복을 어떻게 방지하나요?"
A: 대여 신청 시 해당 제품의 모든 approved/ongoing 상태 대여를 
   조회하여, 신청하려는 날짜 범위와 겹치는지 검증합니다.
   겹치면 신청을 거부합니다.

Q5: "실시간 알림은 어떻게 구현했나요?"
A: 현재는 30초 폴링 방식입니다. 더 실시간성을 높이려면 
   Socket.io 이벤트로 서버에서 클라이언트에 알림을 푸시하는 
   방식으로 개선할 수 있습니다.

Q6: "리뷰 시스템의 신뢰성은?"
A: 양방향 리뷰로 공정성을 확보하고, 완료된 대여에만 작성 가능하여 
   허위 리뷰를 방지합니다. 각자 1회만 작성 가능하며, 
   평균 평점이 자동으로 계산되어 프로필에 반영됩니다.
   또한 제품 상세 페이지에서 해당 제품과 관련된 모든 리뷰를 
   확인할 수 있어, 거래 전 제품과 거래 상대방의 신뢰도를 
   종합적으로 판단할 수 있습니다.
